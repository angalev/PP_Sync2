# Синхронизация Производственной программы

Вы правите свою копию ПП как обычно, в Excel. Программа сравнивает её с боевым
файлом на сервере, показывает все различия и переносит только те, которые вы
отметили галочками.

Ничего не применяется без визуального подтверждения.

## Запуск

```
ПП_синхронизация.exe     # собранная программа, Python не нужен
python main.py           # то же самое из исходников
```

На главном экране два поля: **файл с изменениями** (ваша копия) и **боевой
файл** на сервере. Кнопка «Сравнить» — и внизу таблица различий.

Настройки (`Файл → Настройки…`) хранятся в `C:\ПП_синхронизация\config.json`;
путь можно переопределить переменной окружения `PP_SYNC_CONFIG`. Туда же
складываются резервные копии (`backup\`) и журнал (`journal.csv`). Больше
никаких папок программе не нужно — на сервере она ничего не создаёт, только
читает и сохраняет сам боевой файл.

Если корень диска `C:` закрыт политикой (на рабочих машинах это обычное дело)
или выбранная папка недоступна на запись, программа не падает: она переезжает
в `%LOCALAPPDATA%\PP_sync` и пишет об этом в журнал на главном экране. Если
писать некуда вообще — показывает окно с причиной, а не «WinError 5».

## Как это работает

**«Сравнить»** — боевой файл не меняется вообще:

1. С обоих файлов снимаются рабочие копии во временную папку. Оригиналы
   читаются по одному разу; по сети ходит один файл в одну сторону.
2. Обе копии открываются в скрытом Excel **только на чтение**, каждая в своём
   экземпляре, одновременно. Макросы и события отключены, служебное имя
   автофильтра починено в копии (см. ловушки ниже).
3. Лист читается прямоугольником: значения и формулы, по одному обращению
   к Excel на каждое. Excel закрывается, временная папка удаляется.
4. Строки сопоставляются **по сводному коду X/Y/Z**, столбцы — **по коду из
   строки кодов** (строка 9). Ни номер строки, ни буква столбца роли не
   играют, поэтому файлы могут быть разной ширины.
5. Сравниваются значения по всем общим столбцам (или только по вашему блоку —
   см. «Сравнивать не всё»). Сами формулы не переносятся никогда; если
   значение в копии посчитано формулой, переносится её результат.

Пока вы расставляете галочки, боевой файл никем не открыт.

**«Применить отмеченное»** — единственное место, где боевой файл меняется:

1. Боевой файл копируется в `backup\` — прямо перед записью.
2. Файл открывается через xlwings (`visible=False`) с отключёнными макросами и
   событиями, выставляется `ConflictResolution`.
3. Лист перечитывается заново, и каждая отмеченная ячейка сверяется с тем, что
   вы видели в таблице. Если коллега успел её изменить — она не пишется, о ней
   сказано отдельно. Строки и столбцы ищутся заново (по ключу и по коду), так
   что вставленная кем-то строка записи не мешает.
4. Пишутся только отмеченные ячейки, книга сохраняется (слияние с чужими
   правками), записанное перечитывается и сверяется, Excel закрывается,
   пишется журнал.

Режим общего доступа не отключается, lock-файл не проверяется — одновременная
работа нескольких человек штатная.

## Столбцы — по кодам из строки 9

В строке 9 листа у каждого столбца стоит свой код: `39` — сводный код X/Y/Z,
`7` — трансгаз, `14` — объект, `316` — номер техакта и так далее. Программа
находит столбцы только по этим кодам. Буква для неё — способ показать адрес.

Что это даёт:

* столбцы в файле можно удалять, вставлять и переставлять — настройки менять
  не нужно. ПП 2.0 (335 столбцов вместо 373) работает с теми же настройками,
  что и старый формат;
* копия и боевой файл могут быть **разного формата**. Сравниваются столбцы,
  код которых есть в обоих файлах; про остальные программа говорит в журнале
  на главном экране («В боевом файле нет столбцов (40), которые есть в копии…»);
* у столбца без кода в строке 9 нет и сравнения — программа его не видит.

Все настройки столбцов задаются кодами: «код столбца ключа X/Y/Z», «сравнивать
столбцы», «не сравнивать столбцы», «столбцы с формулами». Диапазон пишется
через дефис: `259-273, 316`. Если в строке кодов два столбца с одним кодом,
программа остановится и назовёт оба.

## Статусы различий

| Статус | Что значит | Можно применить |
|---|---|---|
| `к применению` | в боевом пусто, в копии есть значение | да |
| `перезапись` | в боевом другое значение (подсвечено) | да |
| `очистка` | в копии пусто, в боевом было значение | да |
| `формула в копии` | в копии значение посчитано формулой | да — переносится результат |
| `формула в боевом` | в боевом файле формула — трогать нельзя | нет |
| `строки нет в боевом` | код X/Y/Z есть только в копии | нет, строки не создаются |

## Формулы: расчётные столбцы и ленивые ссылки

Формулы в ПП двух разных сортов, и обращаться с ними надо по-разному.

**Расчётные столбцы.** Там формула держит лист: «Всего» = сумма кварталов,
«% выполнения» = факт / план, блок «Работы по ДО» — подстановка из парного
столбца КОРР. Заменить такую формулу значением значит сломать расчёт, поэтому
программа их не трогает: статус `формула в боевом`, галочка недоступна. Список
лежит в настройке **«столбцы с формулами (коды)»**, по умолчанию — замер на
реальной ПП 2026, коды из строки 9:

```
33, 104, 130, 276, 278, 280, 282, 284, 286, 288, 290, 292, 294, 296, 298, 300,
304, 311, 313, 321, 323, 324, 326, 327
```

Список покрывает оба формата: коды удалённых в ПП 2.0 столбцов (блок «Работы
по ДО» 276–300, «Тип ССП» 304, старые 323/324) просто ничего не находят, а
новые `326`/`327` («Фактическая дата начала/окончания полевых работ») уже в нём.

**Все остальные столбцы.** Там формула — односложная ссылка на соседнюю ячейку
(`=DS515`, `=O152`, `=DM11`): работник не стал впечатывать цифру. Так быть не
должно, и именно из-за этого фактически выполненные объёмы не доезжали до
боевого файла. Такая формула считается обычным значением: сравнивается,
показывается и **заменяется значением из копии**. Больше всего таких ячеек в
датах факта (коды `307`, `308`, `310`) и в `312` «Кол-во (факт)». В окне
подтверждения они посчитаны отдельной строкой, в журнале помечены
`применено, заменена формула`.

**Формула с обеих сторон** — строки нет ни в каком столбце: ни там, ни там
человек ничего не впечатывал, разъехался тот столбец, на который ссылаются.

**Формула, посчитавшая ноль**, — тоже не данные. Пустую ссылку Excel считает
нулём, и в ячейке с форматом даты этот ноль выглядит как `00:00`. Такие
результаты не переносятся и не очищают ячейку боевого файла. Замер на реальной
паре: в копии столбцы `DZ` и `EA` («Дата начала/окончания работ по техакту»)
заполнены формулами `=DO`/`=DP`; из 300 «различий» 143 были таким нулём, и без
этой проверки они уехали бы в боевой файл фальшивыми датами.

**Формула, посчитавшая ошибку** (`#REF!`, `#DIV/0!`), — тоже не данные: текст
ошибки в боевой файл не переносится.

Само содержимое формулы не переносится никогда, ни в какую сторону: её ссылки
относятся к своему файлу. Переносится только результат.

В таблице различий столбцы: галочка, трансгаз, объект, XYZ, столбец (впереди
его код: `[316] Технический акт… / Номер техакта`), ячейка, значение в боевом,
значение в копии, статус и пояснение. Ширину любого столбца
можно тянуть мышью за границу в шапке, двойной щелчок по границе подгоняет
столбец под содержимое.

**Сразу не отмечается ничего.** Пишется ровно то, что отмечено галочками:
ни одной лишней ячейки. Кнопка «Отметить все в таблице» отмечает только то,
что видно сейчас, — то есть с учётом фильтра по трансгазам.

Счётчик внизу читается так: «отмечено 3 изменения из 358 найденных». Если
что-то отмечено у трансгаза, снятого сейчас в фильтре слева, счётчик и окно
подтверждения скажут об этом отдельно — записано будет и оно тоже.

## Что программа не делает

* не создаёт и не удаляет строки — только меняет значения в существующих;
* не переносит формулы (ни из копии, ни поверх формул в боевом);
* не переносит форматирование — ячейка сохраняет своё оформление;
* не трогает копию с изменениями: она только читается.

Про форматирование одно исключение: в столбцах с форматом «Текстовый» (в ПП это,
например, код `54` «Дата и номер письма о согласовании») дата ложится текстом. Excel сам записал бы её как `7/15/2026`
по локали США — программа кладёт то, что видно в копии (`15.07.2026`), и
помечает такую строку пояснением.

## Сравнивать не всё

По умолчанию сравниваются все столбцы, у которых есть код в строке 9. Если вы
отвечаете за свой блок, укажите его коды в настройках («сравнивать столбцы»,
например `259-273, 316-320`) — тогда чужие правки в других столбцах вообще не
будут попадать в таблицу.

Блоки в реальном файле (коды): **259–267** (ЗЭПБ), **268–273** (технический
отчёт), **316–320** (техакт), **307–313** (даты факта и физическое выполнение).

## Проверено на боевом файле

Прогон на копиях реальной ПП — и старого формата (373 столбца, 137 с кодами),
и 2.0 (335 столбцов, 99 с кодами), 1278 строк, 2–2,6 МБ:

* сравнение всех столбцов — **около 8 секунд** на локальном диске, из них
  почти всё — открытие двух книг в Excel (читаются одновременно). Чтение
  листа — меньше секунды на файл, само сравнение — 0,7 с;
* запись 100 ячеек — около 8 с (открытие боевого 3,5 с, запись 0,7 с,
  сохранение 1,5 с); перенос 5901 ячейки — 52 с;
* пара «копия старого формата → боевой 2.0»: сверено 121 410 ячеек, всё, что
  можно было перенести, перенесено, столбцы найдены по кодам;
* формулы целы: число формул до и после записи сходится (минус ленивые
  ссылки, заменённые по замыслу), ни одна не потеряна и не изменена; ячейка с
  формулой в расчётном столбце блокируется статусом и остаётся формулой;
* оформление целое: 430 проверенных ячеек (целевые, соседние и случайная
  выборка) — ноль изменений формата, шрифта, заливки, границ, выравнивания;
* `vbaProject.bin`, сводные и их кэши, элементы управления, рисунки на месте;
  в архиве добавляются только новые `xl/revisions/revisionLog*.xml` — журнал
  общего доступа штатно записывает наши правки.

Служебные имена автофильтра и личных представлений (`_FilterDatabase`,
`*.wvu.*`) после сохранения слегка меняются, но это нормализация самого Excel:
отдельный прогон «открыл и сохранил, не записав ни одной ячейки» даёт ровно то
же. Личные представления при этом целы.

### Ловушки живого файла, под которые программа доработана

1. **Макросы.** При открытии срабатывал `Workbook_Open` и вываливалась модальная
   ошибка VBA с кнопкой End — `DisplayAlerts` её не гасит, невидимый Excel висел
   до ручного нажатия (прогон занял 530 с вместо 8). Книга открывается с
   `AutomationSecurity = ForceDisable` и `EnableEvents = False`: макросы не
   запускаются, `vbaProject.bin` в файле остаётся. На прочие модальные окна
   («Обновить связи», вход в учётную запись) есть сторож
   `ppsync/excel_guard.py`: программа замечает окно, называет его и предлагает
   либо ответить самому, либо прервать работу. Кнопки за пользователя она не
   нажимает — кроме одного окна, «Конфликт имен» про служебное имя: его
   программа закрывает сама (см. ниже).
2. **Автофильтр.** На листе бывает активен фильтр (был по «Сургут ГТ», скрыто
   1262 строки), а `End(xlUp)`/`End(xlToLeft)` пропускают скрытые строки и
   столбцы — карта ключей молча теряла 91 строку. Границы данных и шапки берутся
   только из `UsedRange`.
3. **Формат ключа неоднороден.** Кроме `97575/12/102770` встречается
   `97435.8-9100297753` (86 строк из 1278), поэтому ключом считается любая
   непустая нечисловая строка.
4. **«Конфликт имен» при открытии.** В боевом файле имя диапазона автофильтра
   записано как `_FilterDatabase`, без обязательного префикса `_xlnm.`, и Excel
   при открытии требует его переименовать. Скрытому экземпляру отвечать некому:
   `Workbooks.Open` падает с `Метод Open из класса Workbooks завершен неверно`.
   Две меры, обе включаются галочками в настройках:
   * при сравнении имя чинится в **рабочей копии** — боевой файл для этого
     трогать не нужно. Перед записью оно чинится уже в самом боевом файле
     (`ppsync/name_check.py`): переписывается ровно `xl/workbook.xml` внутри
     книги, остальные части копируются байт в байт, сам файл не подменяется
     (права доступа на общей папке остаются его собственными). Если книга у
     кого-то открыта (лежит `~$…`), правка в боевом файле не делается;
   * если окно всё-таки появилось, на него отвечает фоновый поток
     `DialogWatcher`: вписывает `FilterDatabase_1` и жмёт «ОК». Отвечать должен
     именно отдельный поток — основной в это время стоит внутри COM-вызова.
     Автоответ срабатывает только когда сошлось всё: окно принадлежит нашему
     Excel, заголовок «Конфликт имен», а в тексте найдено имя из списка
     встроенных. Любое другое окно по-прежнему уходит человеку.

   Честная граница: Excel записывает имя обратно в кривом виде при первом же
   сохранении, поэтому починка лечит один запуск — она и делается каждый раз
   заново.
5. **Окно «Учетные записи» на файле из OneDrive.** Если книга лежит в папке
   OneDrive, Excel при открытии может показать окно входа в учётную запись
   (класс `NUIDialog`). Главное окно Excel при этом становится недоступным,
   COM-вызовы не возвращаются, и программа выглядит как «долго считает».
   Класс `NUIDialog` сторож раньше не знал — теперь знает; вдобавок он ловит
   диалоги любого неизвестного класса по признаку «главное окно Excel
   заблокировано». При сравнении книги открываются из временной папки, а не
   из OneDrive, так что там этому окну взяться неоткуда; при записи боевой
   файл открывается со своего места.
6. **Две книги с одним именем.** Боевой файл и копия обычно называются
   одинаково, а Excel не откроет в одном экземпляре две книги с одним именем.
   Рабочие копии называются по-разному и открываются каждая в своём Excel.
7. **Копия открыта у вас в Excel.** Сравнению это не мешает: с открытого
   файла снимается рабочая копия. Читается то, что сохранено на диск, —
   несохранённые правки программа не увидит.
8. **Дата через COM уезжает на часовой пояс.** Запись даты напрямую в COM
   (pywin32) кладёт `29.06.2026 21:00` вместо `30.06.2026`: дата без часового
   пояса сдвигается на разницу с UTC. Поэтому ячейки пишутся через xlwings,
   хотя это втрое медленнее (8 мс на ячейку против 2,4).

## Проверочные прогоны

```
python -m tools.make_test_workbook     # пара синтетических файлов в tests\data
python -m tools.formula_case_check     # все сочетания «формула/значение»
python -m tools.console_check --target "tests/data/ПП_боевой.xlsx" \
                              --source "tests/data/ПП_копия_с_изменениями.xlsx"
python -m tools.apply_check            # полный цикл записи в песочнице
python -m tools.stale_check            # боевой изменился между сравнением и записью
python -m tools.gui_check              # автопрогон GUI (offscreen)
python -m tools.name_fix_check         # починка служебных имён (без Excel)
python -m tools.dialog_answer_check    # автоответ на «Конфликт имен»

python -m tools.real_file_check --source "C:\путь\Производственная программа 2026.xlsm"
python -m tools.transfer_check --target "C:\путь\боевой.xlsm"                                --source "C:\путь\копия.xlsm"
```

`console_check` делает ровно то же, что кнопка «Сравнить», печатает время и
таблицу различий. Ни один из файлов он не меняет — им удобно сравнивать две
реальные копии, ничего не рискуя.

`formula_case_check` собирает пару книг через настоящий Excel и проверяет все
сочетания «формула/значение» в двух видах столбцов: расчётном и обычном.
Столбцы в двух книгах стоят под разными буквами при одинаковых кодах —
заодно проверяется сопоставление по кодам.

`stale_check` разыгрывает работу коллеги: после сравнения в «боевой» файл
вставляются строка и столбец и правится одна из отмеченных ячеек. Программа
должна записать остальное по новым адресам, а чужую правку не тронуть.

`transfer_check` — самый честный прогон на живой паре: переносит из копии
**всё, что можно**, а потом открывает записанный боевой файл заново и сверяет
его с копией ячейка за ячейкой по всей области сравнения. Каждое оставшееся
расхождение раскладывается по причине, поэтому видно, что не перенесено по
замыслу, а что недосмотрено. Отдельно сходится число формул: было, стало и
сколько ленивых ссылок заменено.

`real_file_check` делает из боевого файла две копии, правит в одной несколько
ячеек разного типа, прогоняет полный цикл и сравнивает слепки до/после:
формулы всех листов, оформление, состав частей книги, объединения, условное
форматирование, проверки данных, имена. Исходный файл только читается.

## Что осталось проверить на рабочем ПК

1. **Поведение `ConflictResolution=2` на реальном конфликте.** Открыть файл с
   двух машин, изменить одну и ту же ячейку, применить и посмотреть, что скажет
   проверка «Перечитывать ячейки после сохранения»: если победила чужая правка,
   программа напишет расхождение в журнал и в итоговое окно.
2. **Скорость по UNC.** Локально сравнение — около 8 с, запись — ещё около 8.
   При сравнении по сети идёт только одно чтение боевого файла (копирование
   2,6 МБ), всё остальное локально; при записи — открытие и сохранение книги
   на сервере, они будут дольше.
3. **Автоответ на настоящее окно «Конфликт имен».** Дома окно не
   воспроизводится, автоответ проверен на подставном диалоге того же класса
   (`python -m tools.dialog_answer_check`). На рабочем ПК надо увидеть в
   журнале строку «Excel спросил про служебное имя… — ответил
   FilterDatabase_1». Если вместо неё появится «Не удалось ответить в окне», в
   той же строке будут классы контролов окна — по ним автоответ дорабатывается.
4. **Первый боевой прогон** — на одной-двух правках, при свежем бэкапе.

## Сборка exe

```
build.cmd
```

Собирается `dist\ПП_синхронизация.exe` — **один файл, 39 МБ**, ничего рядом с ним
не нужно. Python на рабочем ПК не требуется, Excel — по-прежнему да. Настройки,
резервные копии и журнал остаются там же, в `C:\ПП_синхронизация`: exe их не
носит с собой, поэтому обновление программы сводится к замене одного файла.

Скрипт сам поставит PyInstaller, если его нет, и соберёт по `build_exe.spec`.
В spec заданы две вещи, без которых сборка молча ломается: данные `xlwings`
(готового хука для него у PyInstaller нет) и `win32timezone` (pywin32 грузит его
лениво, анализатор такой импорт не видит).

Проверить готовый файл, не запуская Excel и ничего не трогая:

```
ПП_синхронизация.exe --selftest
```

Показывает окно с отчётом, пишет `selftest.log` **рядом с самим exe** и
возвращает 0, если всё в порядке. Это ответ на вопрос «почему не работает на
этой машине?»: в отчёте пути (exe, `%TEMP%`, куда распаковался onefile), список
модулей, все папки с причиной отказа («нет прав на запись», «сетевой диск не
подключён») и оба файла — боевой и с изменениями — с их размерами. Первое, что
стоит запустить на рабочем компьютере, если программа ругается.

Окно модальное, поэтому для скриптов есть `--selftest --quiet`: отчёт только
в файл и в код возврата.

У собранной программы нет окна консоли, поэтому необработанная ошибка не могла бы
себя показать — она пишется в `crash.log` **рядом с exe** (человек ищет журнал
там, где запускал) и выводится системным окном с точным путём. Если рядом с exe
писать нельзя — журнал уходит в папку `config.json`, затем в `%TEMP%`.

Замерено на локальной машине: окно открывается за **~2 с** (один файл каждый
запуск распаковывается во временную папку), память — около 70 МБ. Запуск с
сетевого диска будет дольше: копируйте exe на локальный диск.
